# Agent 작업 로그 남기기 (기록)

> 진행한 코드 작업을 다음 작업(사람/Agent)이 이어받을 수 있도록,
> `.claude/Agent/`(저장소 루트 기준)에 작업 로그를 남긴다.
> 짝이 되는 스킬은 [`agent-log-reader`](../agent-log-reader/SKILL.md)(작업 전 로그 참조)다.

---

## 트리거 — 언제 로그를 남기는가

**코드/설정 파일을 실제로 수정한 작업이 끝났을 때** 답변을 마치기 전에 남긴다. 대표 예:

- 기능 추가·변경·삭제 (파일 생성/수정/삭제 포함)
- 리팩토링, 버그 수정, 스키마/패킷/데이터 파이프라인 변경
- 빌드·설정·스크립트 변경

## 하지 않을 것 (로그 생략)

- 코드/파일을 바꾸지 않은 **단순 질의응답·탐색·설명**만 한 경우
- 로그 자체를 쓰는 작업(무한 로그 방지)
- 사용자가 명시적으로 "로그 남기지 마"라고 한 경우

---

## 파일 규칙

- 위치: `.claude/Agent/`
- 파일명: `YYYY-MM-DD-<kebab-slug>.md` (날짜는 `currentDate` 기준, slug은 영문 kebab-case)
  - 예: `2026-07-25-excelgenerator-bytes.md`
- **하나의 작업 단위 = 하나의 로그 파일.** 같은 날 다른 작업이면 파일을 분리한다.
- 같은 작업의 후속/수정이면 기존 파일에 `## 업데이트 (YYYY-MM-DD)` 섹션을 덧붙인다.

---

## 로그 템플릿

```markdown
---
date: YYYY-MM-DD
title: <작업 한 줄 제목>
tags: [영역, 키워드]   # 예: [server, excelgenerator, data]
---

# <작업 제목>

## 목적 / 배경
- 왜 이 작업을 했는지 (요청 맥락, 해결하려던 문제)

## 변경 내용
- 무엇을 바꿨는지 (파일 단위로 구체적으로)
- `경로/파일.cs` — 핵심 변경 요약

## 주요 결정 / 근거
- 대안이 있었다면 왜 이 방식을 택했는지 (다음 사람이 다시 고민하지 않도록)

## 후속 작업 / 주의사항
- 남은 TODO, 알려진 한계, 건드리면 안 되는 것, 함께 봐야 할 파일
- 없으면 "없음"
```

- 각 항목은 한글로, 불릿 위주로 간결하게.
- 코드를 재서술하지 말고 **코드에 안 드러나는 이유·맥락·결정**을 남긴다.

### 압축 기준 — 무엇을 남기고 무엇을 버리는가

로그는 요약이 아니라 **인수인계다.** 기준 질문은 하나 —
**"이 로그가 없으면 다음 작업자가 무엇을 다시 파야 하는가?"** 그것만 남긴다.

| 남긴다 | 버린다 |
| --- | --- |
| 왜 그 방식을 택했는지 (기각한 대안 포함) | 무엇을 했는지의 나열 (diff가 이미 말한다) |
| 겪은 함정과 해결 (다음에 또 밟을 것) | 시행착오의 시간순 서사 |
| 코드에 안 드러나는 제약·지뢰 ("X를 옮기면 Y가 조용히 깨진다") | 파일 내용 재서술 |

- **다른 산출물에 이미 있는 내용은 경로로 참조만 한다.** 커밋 메시지·`일감/`·
  기획 문서(`GameDesign/기획/`)가 담은 것을 로그에 다시 쓰면 원본이 둘이 되어
  한쪽만 갱신될 때 어긋난다. `→ 일감/T-016` · `→ 산업레벨.md 3장` 형태로 가리킨다.
- 로그의 고유 몫은 **결정·근거·지뢰**다. 그 셋이 없으면 로그가 아니라 잡음이다.

---

## 마무리 절차 (필수)

1. 위 규칙으로 `.claude/Agent/YYYY-MM-DD-<slug>.md` 를 작성한다.
2. `.claude/Agent/README.md`의 `INDEX`에 한 줄을 **최신순(위)** 으로 추가한다.
   - 형식: `- [YYYY-MM-DD 제목](파일명.md) — 한 줄 요약`
3. 답변 말미에 "작업 로그를 남겼다: `.claude/Agent/<파일명>`" 한 줄로 알린다.
