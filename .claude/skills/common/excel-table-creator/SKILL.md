# 게임 데이터 엑셀 시트 작성

`GameDesign/Excel/*.xlsx`가 게임 데이터의 **유일한 원본**이다.
여기서 시트를 만들면 파이프라인이 `.cs` · `.bytes` · `.json`을 생성하고 Unity까지 미러링한다.
생성물(`Server/GameData`, `Server/Shared/Data`, `GameDesign/DataLog`, Unity 미러)은 **직접 수정하지 않는다.**

---

## ⚠️ 착수 전 — 이름은 임의로 정하지 않는다

**파일명 · 시트명 · 컬럼명을 마음대로 짓지 않는다.** 후보를 제시하고 사용자에게 확인받는다.

시트명은 곧 생성되는 클래스명(`<시트명>Row`)이고 `.bytes` 파일명이며 Unity 미러 경로다.
한 번 박히면 되돌리는 비용이 크다.

---

## 하드 규칙

### 1. Enum 시트를 제외한 모든 시트는 TID 컬럼을 갖는다

**첫 데이터 컬럼은 `<시트명 접두>TID`다.** 생성기(`TableCodeGenerator.PickKey()`)가
`Type = ID`인 컬럼 또는 **첫 비배열 컬럼**을 키로 잡기 때문에, TID가 앞에 없으면
엉뚱한 컬럼이 키가 된다.

| 시트 | TID 컬럼 |
| --- | --- |
| `ItemTable` | `ItemTID` |
| `CharacterTable` | `CharacterTID` |
| `FishingBasicTable` | `DropTID` |
| `WorkSpeedTable` | `WorkSpeedTID` |

- **키는 유일해야 한다.** 중복되면 `TableSet.From()`이 로드 시점에 예외를 던진다.
- **의미 있는 값이 곧 정체성이면 그 값을 TID로 쓴다.** 예: `WorkSpeedTable`은 적성 등급(0~10)이
  행의 정체성이므로 `WorkSpeedTID`의 값이 곧 등급이다. 별도 TID를 두면 항상 1:1인 컬럼이
  둘이 되어 어긋날 여지만 생긴다.
- **Enum 시트는 예외다.** `Enum.xlsx`는 `EID` / `Name` / `Desc` 구조를 쓴다(아래 참조).

### 2. TID 번호는 재사용하지 않는다

DB에 저장되는 식별자는 **한 번 쓰이면 의미를 바꿀 수 없다.** 엑셀을 고쳐도 이미 디스크에
적힌 정수는 아무도 다시 쓰지 않는다.

- 폐기한 TID를 다른 행에 다시 주면 **옛 DB 행이 조용히 다른 것으로 둔갑한다.**
- 중간에 새 번호를 끼워 넣는 것은 괜찮다(값을 직접 적으므로 뒤가 밀리지 않는다).
- **Enum은 다르다 — 반드시 뒤에만 추가한다.** 중간 삽입하면 뒤 값이 전부 밀린다.

> ⚠️ `Ref` 검사는 **엑셀 안에서 엑셀만** 본다. DB에 살아 있는 TID를 시트에서 지워도
> 검증은 통과하고 DB에만 고아가 남는다. 삭제는 항상 수동으로 확인한다.

→ 상세: [`게임기획코어.md`](../../../../GameDesign/기획/게임기획코어.md) 4장 "식별자 규칙"

### 3. 밸런스 수치 컬럼에는 기본값을 두지 않는다

`Default(Null)`을 비워 두면 **빈 셀 = 오류**(fail-fast)다. 확률·가중치·적성처럼
로직이 읽는 값은 이 상태로 둔다. 실수로 빈 셀이 조용히 0이 되면 그 행이 말없이 죽는다.

기본값을 두는 것은 **비어 있는 게 정상인 컬럼**뿐이다(주로 `Description`).

## 시트 구조 (마커 행)

**A열이 마커**, 나머지 열이 컬럼 정의다. 마커 행 다음 **A열이 빈 행이 컬럼명 행**이고,
그 아래부터 데이터다.

```
     A                 B              C          D
1  (비움)
2  //              아이템 TID      이름        설명 (메모 — 로직 미사용)
3  C&S             a              a           a
4  Type            int            string      string
5  Min
6  Max
7  Default(Null)                              ""
8  Ref
9  (비움)          ItemTID        Name        Description      ← 컬럼명 행
10 (비움)          1              붕어         메모
```

| 마커 | 의미 |
| --- | --- |
| `//` | 한글 설명. 코드에 주석으로 들어간다 |
| `C&S` | 이 컬럼을 누가 쓰는가 (`a` = 양쪽) |
| `Type` | `int`·`long`·`float`·`string`·`bool`·`ID`·`eEnum` (+ `[]` 배열은 `,` 구분) |
| `Min`·`Max` | 값 범위. 벗어나면 파이프라인 실패 |
| `Default(Null)` | 빈 셀일 때 쓸 값. **비우면 "빈 셀 = 오류"** |
| `Ref` | `대상시트.대상컬럼` — 값이 실재하는지 검사 |

마커 행의 순서는 자유이고, 필요 없는 마커 행은 생략해도 된다.

---

## `Ref` — 무결성 검사

`대상시트.대상컬럼` 형태로 적으면 **그 값이 대상 시트에 실재하는지** 검사한다.
코드 생성 **전에** 돌고, 위반을 전부 모아 한 번에 던진다. 다른 워크북의 시트도 참조할 수 있다.

```
Ref    (비움)    WorkSpeedTable.WorkSpeedTID
```

- **`Min`/`Max`보다 낫다.** 범위는 "0~10 안인가"만 보지만, `Ref`는 "그 행이 있는가"를 본다.
  대상 시트가 늘어나면 자동으로 유효 범위가 넓어진다.
- **`?`를 붙이면 빈 셀과 `0`을 허용한다.** "참조가 없을 수도 있는" 컬럼에만 쓴다.
  **`0`이 유효한 값이면 `?`를 붙이지 않는다** — 0번 행과 대조돼야 하기 때문이다.

## 예약 컬럼 — `Description`

**게임 로직에 아무 영향을 주지 않는다.** 기획자가 시트에 남기는 메모다.

- `Default(Null)`에 **`""`** 를 지정해 빈 셀을 정상으로 둔다.
- 생성된 Row 클래스에 `[기획 메모 — 로직에서 읽지 않는다]` 주석이 자동으로 붙는다.

> ⚠️ **로직에 쓰는 수치를 `Description`에 적지 않는다.** 확률·배수를 메모로 적어 두면
> 실제 컬럼과 따로 놀다가 조용히 어긋난다. 계산에 쓸 값은 반드시 자기 컬럼을 갖는다.

---

## Enum 시트 (`Enum.xlsx`)

구조가 다르다. **시트명이 곧 enum 이름**이다.

```
     A        B        C
1  EID      Name     Desc
2  EnumID   Value    Description
3  int      enum     string
4  1        Gold     골드            ← 4행부터 데이터
```

- `None = 0`과 `Max`는 **생성기가 자동으로 붙인다.** 시트에 적지 않는다.
- 생성 타입은 `byte` 기반이다.
- **값은 뒤에만 추가한다** (규칙 2 참조).

## 실행 절차

```powershell
GameDesign/generate-tables.ps1
```

1. 엑셀을 **Excel에서 닫는다.** 열려 있으면 파일 잠금으로 즉시 실패한다.
2. 스크립트를 돌린다. `Ref` 검사 → 코드 생성 → `.bytes` 생성 → C# 9 검사 → Unity 미러.
3. **엑셀과 생성물을 같은 커밋에 담는다.** `GameDesign/DataLog/*.json`의 diff가
   데이터 변경 리뷰 수단이므로 함께 커밋한다.

> **시트를 지우면 그 테이블의 `.cs`·`.bytes`·`.json`이 Unity 미러까지 자동 삭제된다.**
> 손으로 지울 필요가 없다.

> ⚠️ **`DataLog`의 JSON은 enum을 이름으로 덤프한다.** enum 번호를 바꿔도 diff에 아무것도
> 나오지 않으므로, 이 종류의 변경은 리뷰로 잡히지 않는다.

## 체크리스트

- [ ] 파일명·시트명·컬럼명을 **사용자에게 확인**했다
- [ ] 첫 컬럼이 `<시트명 접두>TID`이고 값이 유일하다 (Enum 시트 제외)
- [ ] 폐기된 TID 번호를 재사용하지 않았다
- [ ] 다른 시트를 가리키는 컬럼에 `Ref`를 걸었다 (`0`이 유효하면 `?` 없이)
- [ ] 로직이 읽는 수치 컬럼에 `Default(Null)`을 두지 않았다 (빈 셀 = 오류)
- [ ] `Description`에 `Default(Null) = ""` 를 지정했다
- [ ] 엑셀을 닫고 `generate-tables.ps1`을 돌렸다
- [ ] 엑셀 + 생성물 + `DataLog` diff를 같은 커밋에 담았다
