## 1. 산업 정체성 (제안)

> ⚠️ 제안이다.

| 항목 | 값 |
| --- | --- |
| **심리 정의** | **확실한 스노우볼** |
| 투자 비유 | 복리 장기투자 — 오늘은 어제보다 낫다 |
| 한 줄 | **깊이 갈수록 좋아진다** |
| 회당 산출 | 중간 — 깊이에 비례 |
| 실패율 | 낮음 |
| ~~특별보상(10%)~~ | ❌ **층 폐지 (2026-07-30).** 보석류의 경로 미정 |
| 역할 | **장기 투자** 축 — 유일하게 진행도가 누적된다 |
| 플레이어 개입 | 하강 ↔ 채굴 중 배분 |

채굴은 5개 산업 중 **유일하게 "어제의 진행이 오늘에 남는"** 구조다.
다른 산업이 매일 리셋되는 반복이라면, 채굴은 계속 깊어진다.
산업 택1(자유 변경)에서도 **깊이는 유지된다** — 다른 산업을 하다 돌아와도 그대로다.

### ✅ "깊이가 희귀도를 올린다"가 되살아났다 (2026-07-31)

~~희귀도 분포가 전 산업 동일로 확정되면서 이 방식은 쓸 수 없다~~ —
**분포 통일이 폐지되어 원래 설계가 다시 가능해졌다.** 채굴은 자기 가중치를 직접 갖는다.

이제 **두 가지를 다 쓸 수 있다.** 깊이 구간마다 행을 두고, 그 행의 `ItemTID`와 `Weight`를
함께 바꾸면 된다 (`MiningBasicTable`에 `DepthLevel` 컬럼 추가).

| 방식 | 내용 | 성격 |
| --- | --- | --- |
| **A. 가중치를 올린다** | 깊을수록 상위 등급 `Weight`가 커진다 | **"희귀한 게 더 자주"** — 스노우볼 체감이 직접적 |
| **B. 매핑을 바꾼다** | 확률은 그대로, 같은 자리에 더 값진 광석 | **"같은 등급이라도 더 값진 것"** — 선형 통제 |

| 예시 | 깊이 1 | 깊이 10 | 깊이 30 |
| --- | --- | --- | --- |
| 하위 등급 | 돌덩어리 | 철광석 | 티타늄 원석 |
| 상위 등급 | 은광석 | 백금광석 | 미스릴 |
| 상위 비중(A) | 낮음 | 중간 | **높음** |

> ⚠️ **A는 강력한 만큼 위험하다.** 깊이가 확률을 건드리면 깊은 유저와 얕은 유저의
> 기대값 격차가 **지수적으로** 벌어진다. B는 아이템 가치 차이로 **선형** 통제된다.
> **A와 B를 섞되 A의 기울기를 완만하게** 두는 것을 권장한다 —
> "확실한 스노우볼"이라는 심리 정의는 A가 있어야 체감되지만, 격차 제어는 B가 담당한다.

> **깊이 상한이 곧 A의 상한이다.** 상한 없이 A를 쓰면 무한 스케일링이 된다.

## 2. 채취 특성 (제안)

```
깊이 0 ─하강→ 깊이 N ─채굴→ 광석 (깊을수록 등급↑)
```

| 파라미터 | 값 | 비고 |
| --- | --- | --- |
| 채취주기 | **30초** ✅ | 전 산업 공통 → [자원채취](../README.md) 2.1 |
| 회당 산출 | 중간 ⚠️ | 깊이에 비례. 수치 미정 |
| 실패율 | 낮음 ⚠️ | 수치 미정 |
| 희귀도 분포 | **채굴 고유** ✅ | 2026-07-31. 깊이가 **가중치와 매핑을 모두** 바꿀 수 있다 (1장) |
| ~~특별보상(10%)~~ | ❌ 폐지 | 2026-07-30. 보석류는 희귀도 롤 편입 검토 |
| 특이 규칙 | 깊이 누적 | 리셋되지 않음 |

> ⚠️ **하강 속도를 30초 판정 기준으로 잡는다.** 하루 2,880회이므로
> 판정당 깊이 증가를 크게 잡으면 며칠 만에 최대 깊이에 도달해 장기 목표가 소진된다.

### ⚠️ 깊이와 산업 레벨은 성격이 다르다 (2026-08-01)

[산업 레벨](../산업레벨.md)은 **조건을 채워 해금하고, 배치할 때 고르는** 것이다.
채굴의 깊이는 **시간이 쌓아 주는** 것이고, 그것이 "확실한 스노우볼"의 근거다.
**두 축을 어떻게 나눌지 결정이 필요하다.**

| 안 | 내용 | 평가 |
| --- | --- | --- |
| A. 깊이를 레벨로 흡수 | 하강 메커니즘 폐기. 깊이 = 채굴 레벨 | 깔끔하지만 **채굴의 정체성이 사라진다** |
| **B. 두 층으로 둔다** | **레벨 = 갱도**, 깊이 = 그 갱도 안에서의 누적 | **권장** |
| C. 채굴만 레벨 없음 | 5종 중 하나만 규칙이 다르다 | 비권장 |

**B를 권장한다.** 갱도를 고르고 그 안에서 깊이가 누적된다.
갱도를 바꿔도 **깊이는 갱도별로 따로 보관**해야 갱도 변경이 후퇴가 되지 않는다.

> ⚠️ B는 `MiningBasicTable` 행 수가 **`갱도 × 깊이 구간 × 아이템 수`** 가 된다.
> 채굴만 시트가 급격히 커지므로 갱도 수·깊이 구간 수를 작게 시작한다.

### 깊이 (제안)

- 깊이는 **유저별로 누적**되며 리셋되지 않는다.
- 깊이 구간마다 산출 광석과 희귀도 분포가 달라진다.
- 더 깊이 가려면 시간(또는 재료)이 든다.

| 논점 | 권장 |
| --- | --- |
| 하강과 채굴을 동시에? | **택1** — 선택이 생긴다 (지금 캘까, 더 갈까) |
| 깊이 상한 | 있음 — 없으면 무한 스케일링 |
| 오프라인 중 진행 | 자동 채굴 (현재 깊이에서) |

> 이 "지금 캘까 / 더 내려갈까"가 채굴의 유일한 의사결정이다.
>
> ✅ **해소 (2026-07-27):** 요일 로테이션이 "전 산업 상시 가동 + 요일 효율 보너스"로
> 확정되면서 **채굴도 매일 진행된다.** 주 1회만 열려 깊이 누적이 정체되던 문제는 사라졌다.
> 배정 요일(목요일 제안)에는 보너스 배수가 붙는다. → [자원채취](../README.md) 2.3

## 3. 산출물

| 구분 | 내용 |
| --- | --- |
| 기본 자원 | 광석 (깊이별 등급) |

> [특성](../../특성/README.md)와 자연스럽게 연결된다.

## 4. 데이터 설계 (제안)

| 테이블 | 컬럼 |
| --- | --- |
| `MineDepthTable` | `DepthLevel`, `DescendCycles`, `YieldCount`, `UnlockCondition` |
| `MiningBasicTable` | `DropTID`(키), **`IndustryLevel`**(갱도), `DepthLevel`, `ItemTID`, `Weight` |
| ~~`MiningSpecialTable`~~ | ❌ **폐지 (2026-07-30).** 특별보상 층이 없어졌다 |

현재 깊이는 **유저 DB**에 저장한다.

- **현재 `MiningBasicTable`은 `DepthLevel` 없이 6행이다** (2026-07-31 생성).
  깊이 시스템이 구현되면 컬럼을 추가하고 구간마다 6행씩 늘린다.
- `DescendCycles`는 초가 아니라 **판정 횟수**로 둔다 (30초 고정이므로 초를 쓸 이유가 없다).
- **`Rarity` 컬럼을 두지 않는다.** 희귀도는 `ItemTable.GlobalRarity`가 원본이고,
  드롭 시트는 `ItemTID` + `Weight`만 갖는다. **가중치가 곧 채굴의 분포다.**
  → [자원채취](../README.md) 2.4
- `MiningBasicTable` 행 수 = `깊이 구간 × 6`. 깊이를 30단계로 두면 180행이 된다.
  깊이마다 전 등급을 채우지 말고 **구간 단위**(1~5, 6~10 …)로 묶는 편이 관리하기 쉽다.
- **아이템 TID는 채굴 대역 `40001~`** 이며, 깊이 구간이 늘면 `40007~`로 이어 붙인다.

## 5. 결정 필요

1. 깊이 개념을 넣는가? (넣지 않으면 농사·벌목과 차별점이 약하다)
2. **깊이 1단계 하강에 필요한 판정 횟수는?** (하루 2,880회 기준으로 역산)
3. 깊이 상한은?
4. 하강에 재료(곡괭이·연료)가 소모되는가?
5. 깊이가 리셋되는 상황이 있는가? (붕괴 이벤트 등 — P1 관점에서 비권장)
5-1. **깊이와 산업 레벨을 어떻게 나누는가?** (2장 — **B안(갱도 × 깊이) 권장**)
     B안이면 **갱도별로 깊이를 따로 보관**해야 한다
6. `ItemType.Mining` 주석이 "채광"인데 기획 용어는 "채굴"이다. 용어를 통일할 것

> 해소됨: 채취주기 30초 ✅ / 주 1회 문제(요일 구조 전환) ✅
