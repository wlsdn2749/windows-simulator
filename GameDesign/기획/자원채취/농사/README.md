## 1. 산업 정체성 (제안)

> ⚠️ 제안이다. 5개 산업이 서로 다른 리듬을 갖게 하기 위한 차별화 축.

| 항목 | 값 |
| --- | --- |
| **심리 정의** | **안정적인 수익** |
| 투자 비유 | 적금 — 오늘도 어제만큼 들어온다 |
| 한 줄 | **가장 많이, 가장 확실하게 나온다** |
| 회당 산출 | **가장 많음** (5종 중 1위) |
| 실패율 | **없음** — 심으면 반드시 나온다 |
| ~~특별보상(10%)~~ | ❌ **층 폐지 (2026-07-30).** 변종 작물의 경로 미정 |
| 역할 | 경제의 **기반 물량** 공급 |
| 플레이어 개입 | 파종 시 작물 **선택** |

> **희귀도 분포를 농사만 좁게 둘 수 있다** (2026-07-31 — 분포 통일 폐지).
> 농사의 차별점은 **회당 산출 1위 + 실패 없음**이고, 여기에
> **분포를 하위 등급에 몰아** "많이 나오지만 흔한 것 위주"라는 적금 감각을 수치로 만들 수 있다.
> 낚시(상위 편중·소량)와 정확히 반대편에 선다.

농사는 **양으로 승부하는 산업**이다. 실패가 없고 분포가 좁아 산출이 예측 가능하다.
"오늘 얼마나 벌었나"가 아니라 "꾸준히 쌓인다"가 농사의 감각이다.

> ⚠️ **주기 통일(30초)로 "가장 느리다"는 정체성이 사라졌다.**
> 기존 기획의 "장주기 대량 산출"에서 **장주기가 빠지고 대량만 남았다.**
> 아래 2장에서 파종 구조를 이에 맞게 재해석했다.

## 2. 채취 특성

| 파라미터 | 값 | 비고 |
| --- | --- | --- |
| 채취주기 | **30초** ✅ | 전 산업 공통 → [자원채취](../README.md) 2.1 |
| 회당 산출 | **가장 많음** ⚠️ | 5종 중 1위. 수치 미정 |
| 실패율 | **없음** ✅ | 심으면 반드시 나온다 |
| 희귀도 분포 | **농사 고유** ✅ | 2026-07-31. `FarmingBasicTable.Weight`가 농사의 분포다 |
| ~~특별보상(10%)~~ | ❌ 폐지 | 2026-07-30. 변종 작물은 희귀도 롤 편입 검토 |

### ⚠️ 파종 구조 재해석 필요 — 주기 통일의 직접 충돌

기존 기획은 `파종 → 성장 대기 → 수확`이라는 **긴 사이클**이었고,
"짧은 작물 vs 긴 작물"의 트레이드오프가 농사의 유일한 의사결정이었다.

**채취주기가 30초로 통일되면서 이 구조가 성립하지 않는다.**
30초마다 수확이 일어나면 "심고 기다린다"는 감각이 사라지고,
작물별 `GrowSec`(성장시간)이 갈 자리가 없다.

| 안 | 내용 | 평가 |
| --- | --- | --- |
| **A. 파종 = 드랍 세트 선택** | 심은 작물이 `FarmingDropTable`의 어느 세트를 쓸지 정한다. 30초마다 그 작물이 나온다 | **권장.** 주기 통일과 정합적이고 구현이 단순 |
| B. 이중 타이머 | 30초 판정은 "성장 진행도"만 쌓고, 작물별 `GrowSec`에 도달하면 수확 | 농사만 다른 규칙을 갖게 됨. 정산 복잡 |
| C. 파종 선택 폐기 | 농사도 다른 산업처럼 그냥 나온다 | 농사의 유일한 개입이 사라짐. 비권장 |

**A안을 택할 경우** "미리 정하고 기다린다"는 맛을 살리려면
**선택 변경에 쿨타임**을 둔다 (예: 하루 1회 또는 요일 경계마다).
매 순간 바꿀 수 있으면 선택이 아니라 최적값 고르기가 된다.

> 이 결정은 [자원채취](../README.md) 2.1 주기 통일의 직접적 귀결이다.
> 농사의 정체성 절반이 여기 걸려 있으므로 **채취 구현 전에 정해야 한다.**

### ⚠️ 파종(A안)과 산업 레벨이 같은 일을 한다 (2026-08-01)

[산업 레벨](../산업레벨.md)도 **"슬롯이 어떤 드롭 세트를 쓸지 고르는 것"** 이다.
위 A안(파종 = 드랍 세트 선택)과 정확히 겹친다.

| 안 | 내용 | 평가 |
| --- | --- | --- |
| **A. 파종을 레벨로 흡수** | 농사 레벨이 곧 작물 세트. `CropTable`을 만들지 않는다 | **단순** |
| B. 두 층으로 분리 | 레벨 = 밭 등급, 작물 = 그 안에서의 세트 선택 | 농사만 배치 UI에 칸이 하나 더 생긴다 |

> A를 택하면 **"파종"은 이름으로만 남고** 농사의 개입 지점이 다른 4종과 같아진다.
> B를 택하면 농사가 유일하게 선택 칸이 둘인 산업이 된다.
> **어느 쪽이든 농사 고유의 감각을 하나 내주게 된다** — 이것이 이 결정의 대가다.

## 4. 데이터 설계 (제안)

| 테이블 | 컬럼 |
| --- | --- |
| `CropTable` | ⚠️ **만들지 않았다.** 파종을 레벨로 흡수하면 불필요하다 (2장 A안 — 현재 데이터가 이쪽) |
| `FarmingBasicTable` | `DropTID`(키), **`IndustryLevel`**, `ItemTID`, `Weight`, `Description` ✅ **38행 생성됨** |
| ~~`FarmingSpecialTable`~~ | ❌ **폐지 (2026-07-30).** 특별보상 층이 없어졌다 |

> ⚠️ **실제 시트는 위 표의 옛 구상(`CropTID`·`Rarity`)이 아니라 다른 4종과 같은 형태다**
> (2026-08-02 정정). 레벨 이름은 텃밭 · 밭 · 농장 · 대농장 · 신성한 대지이며
> `IndustryLevelTable`에 있다. **즉 데이터는 이미 A안으로 깔려 있다.**
> → [산업 레벨](../산업레벨.md) 5.2 · 일감 T-014

> **`GrowSec` 컬럼은 A안 채택 시 삭제한다.** 주기가 30초로 고정되면 성장시간이 갈 자리가 없다.
> B안(이중 타이머)을 택하면 유지한다. → 2장 참조

## 5. 결정 필요

1. **파종 구조를 A/B/C 중 무엇으로 가는가?** (2장 — 농사 정체성의 절반. **최우선**)
   → **산업 레벨이 들어오면서 A안이 레벨과 겹친다.** 흡수할지 두 층으로 둘지 함께 정한다
2. A안이면 작물 선택 변경 쿨타임은? (하루 1회 / 요일 경계 / 자유)
3. 작물 종류는 몇 개인가?
4. 밭(슬롯) 개념이 있는가? 여러 작물 동시 재배 가능한가?
5. 파종에 씨앗 아이템이 소모되는가, 무료인가?
6. 회당 산출량 수치는? (5종 중 1위라는 것만 확정)

> 해소됨: 채취주기 30초 ✅ / 실패 없음 ✅ / 희귀도 분포 가장 좁음 ✅
> 사라짐: "수확하지 않고 방치하면?" — 30초 자동 수확이라 방치 개념이 없어졌다
