## 2. 낚시 루프

### 2.1 판정 루프 (30초) — 실패 없음

```
판정 ── 반드시 보상
  │
  ├─ ① 채취 보상 (분기 없음)
  │        └─ 가중치 롤 한 번 ← FishingBasicTable (가중치·어종 모두 낚시 것) ✅
  │             예) 붕어 6590 / 잉어 2000 / 월척 붕어 1000 …
  │
  └─ ② CommonRewardTable 롤 (①과 별개, 매 판정)
          └─ 티켓 · 고유 아이템
```

> ~~① 기본 / 특별 분기 (9 : 1)~~ **폐지 (2026-07-30).** 층 분기가 없어졌다.
> ~~희귀도 롤 → 아이템 매핑 2단계~~ **폐지 (2026-07-31).** 한 단계로 되돌렸다.

채취 속도는 `적성 × (1 + Σ가산) × Π승산`으로 정해진다
(→ [작업슬롯](../../작업슬롯/README.md) 3.4). 서버가 굴리는 롤은 **판정당 2회**(채취 → 공통보상).

### 도파민 정의가 요구하는 것

"확실한 도파민"이 되려면 **자주 · 즉각 · 배신 없이** 보상이 와야 한다.

| 조건 | 현재 상태 |
| --- | --- |
| 배신 없음 | ✅ 실패 폐기로 충족 |
| 자주 | ✅ 30초 주기 |
| 즉각 | ✅ 위젯에서 바로 보임 |
| **특별한 게 자주** | ⚠️ **수단이 생겼다** — 수치는 미정 (2026-07-31) |

#### ✅ 분포 통일 폐지로 수단이 돌아왔다 (2026-07-31)

~~낚시의 특별보상 비율을 20%로 올린다~~ (층 폐지로 무산) → **희귀도 분포를 낚시만 상위로 기울인다.**

**희귀도 분포가 전 산업 동일이라는 확정이 폐지되면서**, 낚시의 `FishingBasicTable`이
자기 가중치를 직접 갖게 됐다. 다른 산업보다 **상위 등급 비중을 높이면**
"특별한 게 흔한 산업"이라는 체감이 수치로 만들어진다.

| | 다른 산업 | 낚시 |
| --- | --- | --- |
| 회당 산출 | 중간~많음 | **적음** |
| 상위 등급 비중 | 기준 | **높임** ← 도파민의 근거 |

> **"적게 자주, 대신 좋은 게 잘 나온다"** 가 낚시의 수치 정의가 된다.
> 회당 산출이 적은 것과 맞물려 총 기대값은 다른 산업과 균형을 잡는다.

> ⚠️ **얼마나 기울일지는 미정이다.** 너무 기울이면 낚시가 최적해가 되어 다른 산업이 죽고,
> 조금 기울이면 체감이 안 난다. → [자원채취](../README.md) 5장 결정 필요 4번

### 낚시에는 고유 메커니즘이 없다 — 대신 수치로 가른다

낚시는 **5종 중 유일하게 "고르고 지켜보기만 하는" 산업**이다.

| 산업 | 개입 지점 | 고유 메커니즘 | 수치 차별화 |
| --- | --- | --- | --- |
| 농사 | 파종 작물 선택 | 있음 | 회당 산출 최다 |
| 벌목 | 벌목 강도 조절 | 자원 고갈·재생 | 산출이 자원량 비례 |
| 채굴 | 하강 ↔ 채굴 배분 | 깊이 누적 | **깊이가 분포를 올린다** |
| 사냥 | 사냥터 선택 | 사냥터 분리 + **보스** | 사냥터별 드랍 |
| **낚시** | **없음** | **없음** | **상위 등급 비중을 높인다** |

**심리 정의상 개입이 없는 게 맞다.** "확실한 도파민"은 조작을 요구하지 않는 게 자연스럽고,
P1(주의를 뺏지 않는다)과 가장 잘 맞는 산업이 된다.

**2026-07-31 기준 낚시의 차별화는 수치 두 개로 선다** — 회당 산출(적음) + 희귀도 분포(상위 편중).
메커니즘이 없다는 사실은 그대로지만, **차별화 수단이 통째로 비어 있던 상태는 해소됐다.**

> ~~**낚시터 확장은 여전히 열린 선택지다.**~~ / ~~낚시터를 계속 1개로 둘지
> "조작 없는 산업"으로 확정할지를 정해야 한다.~~

#### ✅ 산업 레벨이 낚시터를 대신한다 (2026-08-01)

**낚시터를 따로 만들지 않는다.** [산업 레벨](../산업레벨.md)이 도입되면서
"어디서 낚을지"는 **낚시 레벨**이 담당한다 — 5종 전부가 같은 구조를 쓴다.

| | 이전 | 현재 |
| --- | --- | --- |
| 개입 지점 | **없음** (5종 중 유일) | **배치할 때 레벨 선택** |
| 데이터 | `FishingSpotTable` (미생성) | `FishingBasicTable.IndustryLevel` 컬럼 |
| 차별화 | 회당 산출 + 희귀도 분포 | 위 둘 + **레벨별 어종 구성** |

**"고유 메커니즘이 없는 유일한 산업"이라는 상태가 해소된다.**
다만 레벨 선택은 **배치할 때 한 번**이라 상시 조작이 아니므로,
"조작 없는 산업"이라는 P1 정합성은 그대로 유지된다.

### ⚠️ 드롭 시트는 첫 컬럼에 고유 `DropTID`를 둔다

ExcelGenerator는 **단일 컬럼 키만** 지원한다 — `Type = ID`인 컬럼이 있으면 그것을,
없으면 **첫 비배열 컬럼**을 자동으로 키로 잡고, 값이 중복되면 로드 시점에 예외를 던진다.

예를 들어 `(SpotTID, ItemTID, Weight)` 형태로 만들면 `SpotTID`가 키가 되어
**같은 낚시터의 행이 2개 이상인 순간 깨진다.**
가중치 롤 성격의 시트는 첫 컬럼에 `ID` 타입 `DropTID`를 두고,
`SpotTID` 같은 그룹 축은 일반 컬럼으로 둔 뒤 서버가 로드 후 그룹 인덱스를 만든다.
(이 규칙은 특별 테이블 때문에 생겼지만, 그룹 축이 붙는 모든 시트에 그대로 적용된다.)

`FishingBasicTable`은 `(희귀도 → 아이템)` **1:1 매핑**이라 `Rarity`가 그대로 키가 된다.
채굴처럼 축이 하나 더 붙는 산업(깊이 구간)은 Basic도 `DropTID` 방식이 필요하다.

### `ItemTID` 참조 검사 (`Ref` 마커)

드롭 시트의 `ItemTID`는 오타나 삭제된 아이템이어도 타입(int)은 멀쩡해서
`.bytes`까지 그대로 만들어지고, **실제 드랍이 일어나는 런타임에야** 터진다.
이를 막기 위해 엑셀 마커 행에 `Ref`를 추가했다.

| 마커 | 값 | 의미 |
| --- | --- | --- |
| `Ref` | `ItemTable.ItemTID` | 이 컬럼 값이 대상 시트·컬럼에 실재해야 한다 |
| `Ref` | `ItemTable.ItemTID?` | `?`를 붙이면 빈 셀·`0`(참조 없음)을 허용 |

`GameDesign/generate-tables.ps1` 실행 시 **코드 생성 전에** 검사하고, 위반이 있으면
전부 모아 출력한 뒤 파이프라인을 중단한다.

**낚시 테이블에 두지 않는 것:**

| 항목 | 어디에 있나 |
| --- | --- |
| `CycleSec` (30초) | 전역 상수 |
| 티켓·고유 아이템 | `CommonRewardTable` |
| `Rarity` 중복 컬럼 | `ItemTable.GlobalRarity`가 원본 |

> **희귀도 가중치는 여기 있다.** `FishingBasicTable.Weight`가 낚시의 분포다
> (2026-07-31 — `RarityWeightTable` 폐지).

> ~~낚시터를 늘릴 때 `SpotTID` 행만 추가하면 되도록 처음부터 키에 넣어 둔다~~ —
> **`SpotTID`는 만들지 않는다** (2026-08-01). 그 자리를 `IndustryLevel`이 차지했다.
> 밸런스 수치는 `GameDesign/Excel/*.xlsx`가 원본. 수정 후 `GameDesign/generate-tables.ps1` 실행.
