## 1. 게임의 목적 — 섬 개발

### 1.1 문제 인식 — 키우기류에는 대목표가 없다

참고작 두 개(**테스크바 히어로**, **슬레이어 키우기**)를 해 보고 든 생각이다.

- 키우기류에는 **'성장' 말고 큰 대목표가 없다.** 성장하는 것 자체가 목표이고
  엔드 콘텐츠라고 할 것이 없다.
- 모델로 잡은 테스크바 히어로도 마지막 스테이지를 클리어하면
  **무한 파밍 + 아이템 작 + 작한 아이템 거래소 등록**이 전부다.
- **스토리조차 없다.**

우리 게임도 지금 구조 그대로면 같은 자리에 도착한다.
승패 조건이 없고(확정), 후반 목표가 자원 축적뿐이면 특성 만렙 이후 플레이 이유가 사라진다
— [`기획평가.md`](../../기획평가.md) 2.3에 이미 🔴로 적혀 있는 문제다.

### 1.2 제안 — 썩은 무인도를 사서 개발한다

우리가 참고하는 느낌은 **팰월드(일을 시킨다) + 테스크바 히어로(방치로 자란다)** 다.
여기에 맞는 컨셉을 붙인다.

> **플레이어는 싼값에 섬을 샀다. 와 보니 아무것도 없는 썩은 무인도였다.**
> **이제 그 섬을 개발한다.**

기존 확정 사항이 이 컨셉 위에서 전부 자연스럽게 읽힌다 — 컨셉을 위해
시스템을 바꾸는 것이 아니라, **이미 있는 시스템에 이름을 주는 것**이다.

| 기존 시스템 | 섬 컨셉에서의 의미 |
| --- | --- |
| [작업슬롯](../../작업슬롯/README.md) | **개간한 땅.** 늘어날수록 섬이 커진다 |
| 캐릭터 | **섬에서 일하는 일꾼** |
| 1차 산업 5종 | 섬에서 나는 것 — 농사·벌목·낚시·채굴·사냥 |
| [거래](../../거래/README.md) 거래소 | **섬 밖의 시장.** 잉여 산물을 내다 판다 |
| 계정 레벨 (신규 · 3장) | **섬주인 본인** |
| 섬 가치 랭킹 (신규 · 6장) | 개발한 섬끼리의 경쟁 |

### 1.3 왜 이게 R1의 답이 되는가

- **"왜 계속 하는가"에 서사가 생긴다.** 지금은 "수치가 오르니까"뿐이다.
- 방치형의 성장이 **"내 섬이 나아진다"** 로 번역된다 — 같은 숫자가 다르게 읽힌다.
- 스토리를 본격적으로 만들 필요가 없다. **상황 설정 한 줄**로 충분하다.
  (P1 — 주의를 뺏지 않는다. 읽어야 하는 스토리는 이 게임에 맞지 않는다)

> ⚠️ **컨셉만으로 R1이 닫히지는 않는다.** "왜 계속 하는가"의 기계적인 답은
> 6장의 랭킹이 담당하는데, 그 점수 기준이 아직 미확정이다.

## 2. UI 배치 — 좌 / 중 / 우 3열

레퍼런스가 있어 배치는 이미 유리한 상태다. 아래는 **지금 시점의 생각**이며,
개발하면서 변경이 필요하면 다시 공유한다.

| 열 | 담는 것 |
| --- | --- |
| **왼쪽** | 획득한 **캐릭터 인벤** · **장비 인벤** · **자원 인벤** · **특성창** |
| **중앙** | **작업 슬롯** |
| **오른쪽** | **거래소** · **상점** |

### 2.1 근거 — 동선이 한 방향이다

- 왼쪽에 들어온 캐릭터·장비를 **중앙의 작업 슬롯으로 끌어다 배치**한다.
- 슬롯을 클릭하면 그 슬롯이 **전체화면으로 열리고**, 거기서 캐릭터에 **장비를 끌어 착용**한다.
- 오른쪽은 결과물의 출구(거래소)와 입구(상점)다. **왼쪽에서 중앙으로, 중앙에서 오른쪽으로**
  흐름이 한 방향이라 헷갈리지 않는다.

### 2.2 현재 목업과의 차이

`게임UI목업.html`(v1 · 폐기)과 배치가 다르다. **인벤토리의 위치**가 핵심 차이다.

| | 현재 목업 | 이 제안 |
| --- | --- | --- |
| 왼쪽 | 캐릭터 (수치·장비·적성) | 캐릭터 인벤 · **장비 인벤** · **자원 인벤** · **특성창** |
| 중앙 | 작업슬롯 **+ 인벤토리(탭)** | **작업슬롯만** |
| 오른쪽 | 거래소 · 상점 | 거래소 · 상점 (동일) |

**인벤토리가 중앙에서 왼쪽으로 옮겨진다.** 중앙은 작업 슬롯 전용이 되고,
끌어다 놓는 재료(캐릭터·장비·자원)가 전부 왼쪽에 모인다.

### 2.3 [게임 UI](../../게임UI/README.md) 6장 Q8에 대한 답

> Q8. 3열 패널을 동시에 띄우는가? 바탕화면 위젯에서 그만한 창을 상주시키는 것은 P1과 부딪힌다.

**3열은 "필요할 때 여는 큰 창"이다.** 바탕화면에 상주하는 것은 위젯뿐이고,
경영·배치를 할 때만 3열 패널을 연다. 이렇게 두면 P1(주의를 뺏지 않는다)과 충돌하지 않는다.

## 3. 섬주인 — 계정 레벨과 전역 특성

### 3.1 섬주인은 배치되지 않는다

내가 섬을 개발하러 왔으니, **나 자신**에 해당하는 성장 축이 있어야 한다.

| 항목 | 내용 |
| --- | --- |
| 정체 | **계정 그 자체.** 레벨과 전역 특성을 갖는다 |
| 슬롯 배치 | **불가.** 섬주인은 일하지 않는다 — 일은 캐릭터가 한다 |
| 효과 | 전역 특성으로 **모든 슬롯의 작업 효율**에 기여 |

### 3.2 `CharacterTID 1 '유저 캐릭터'` 폐기

지금 [`CharacterTable`](../../../DataLog/CharacterTable.json)에 있는
`TID 1 '유저 캐릭터'`(전 산업 적성 1, 기본 지급)는 **섬주인 개념이 들어오면 자리를 잃는다.**
섬주인은 배치되지 않으므로 캐릭터 테이블에 있을 이유가 없다.

- **TID 1은 폐기하고, 시작 캐릭터는 일반 캐릭터(1001~) 중에서 지급한다.**
- ⚠️ **TID 1은 영구 결번이다.** [`게임기획코어.md`](../../게임기획코어.md) 4장 식별자 규칙 —
  *"폐기한 번호를 되쓰면 옛 DB 행이 다른 것으로 둔갑한다."*
  다른 캐릭터에 1번을 다시 붙이지 않는다.

### 3.3 특성 시스템 재정의

[특성](../../특성/README.md) 문서는 특성을 **산업별 패시브 + 산업별 액티브**로 잡고 있다.
섬주인이 들어오면 이 구조를 바꾸는 것이 낫다.

| | 기존 기획 | **이 제안** |
| --- | --- | --- |
| **패시브** | 산업별 · 자원 소모로 해금·레벨업 | **계정 레벨 포인트로 찍는 전역 공통 특성** |
| **액티브** | 플레이어가 발동하는 부스트 | **계정 레벨 도달 시 자동 해금** · 1회 발동 1시간 · **하루 N회** |
| **산업별 특성** | 있음 | **폐지** |

#### 왜 산업별 특성을 폐지하는가

**산업별 강화는 이미 두 시스템이 담당하고 있다.**

| 시스템 | 산업별 차이를 만드는 방식 |
| --- | --- |
| **캐릭터 적성** | 적성이 곧 기본 작업속도. 배치가 퍼즐이 된다 ([작업슬롯](../../작업슬롯/README.md) 5장) |
| **장비** | 무기1·장신구2·보석1. 효과는 가산으로 붙는다 (일감 T-002) |

여기에 산업별 특성까지 얹으면 **같은 일을 하는 축이 셋**이 된다.
특성은 **전역**만 맡고, 산업별 차이는 캐릭터·장비에 맡긴다.

> ⚠️ **대가: 채취 자원의 소비처가 하나 줄어든다.**
> 기존 기획에서 자원은 "특성 해금 재료"로 소모됐다. 그 자리를
> **5장의 캐릭터 먹이기**와 **4장의 즉시 판매**가 대신한다.

#### 액티브 — 계정 레벨로 해금, 하루 N회

**슬레이어 키우기** 구조를 참고하되 **광고를 뺀다.**

| | 슬레이어 키우기 | **이 제안** |
| --- | --- | --- |
| 해금 | 처음부터 | **계정 레벨 5 · 10 · 20 · 40 도달 시 자동 해금** |
| 발동 조건 | **광고 시청** | **없음.** 그냥 누르면 된다 |
| 지속 | 1시간 | **1시간** (동일) |
| 횟수 | 하루 2회 | **하루 N회 · 일일 리셋** (N 미정) |

**효과 4종 후보** (슬레이어 키우기의 골드/경험치/아이템드랍률/조각드랍률 → 본 게임 대응):

| 후보 | 대상 |
| --- | --- |
| 골드 획득 증가 | 즉시 판매·거래 수익 |
| 경험치 획득 증가 | 캐릭터 → 계정 경험치 (5장) |
| 아이템 드랍률 증가 | 희귀도 롤 또는 회당 산출 |
| **작업속도 증가** | 채취 주기 |

> ⚠️ **작업속도 효과는 반드시 `가산` 항으로 넣는다.**
> [작업슬롯](../../작업슬롯/README.md) 3.4의 `속도 = 적성 × (1 + Σ가산) × Π승산`에서
> **승산으로 두면 가산 전체를 함께 부풀려** 후반 밸런스가 무너진다.

#### 부수 효과 — 설계 원칙 P3의 답 후보 (일감 T-013)

요일 로테이션이 폐지되면서 **P3("하루 단위로 달라진다")가 근거를 잃었고**,
현재 게임에는 하루 주기 장치가 하나도 없다.

**액티브의 일일 리셋이 그 자리를 대신할 수 있다.**
"오늘 몫의 부스트를 언제 쓸까"가 하루 단위 판단이 되기 때문이다.

- 다만 P1(주의를 뺏지 않는다)과의 거리를 확인해야 한다.
  **"안 쓰면 손해"가 되면 접속을 강제하는 장치**가 된다.
- 완화: 지속 1시간이 길고 부스트가 필수가 아니면, 놓쳐도 큰 손해가 아니다.

## 4. 골드 — 즉시 판매와 화폐 순환

### 4.1 골드는 이미 있다

`CurrencyType.Gold = 1`은 **이미 구현돼 있다**
(`Server/GameData/Enum.cs` · `S_CurrencyResponse` · 일감 T-007).

**없는 것은 화폐가 아니라 "버는 길"과 "쓰는 길"이다.** 이 절은 그 둘에 대한 제안이다.

### 4.2 아이템의 두 갈래 처분

작업으로 나오는 5개 산업의 아이템이 인벤토리에 쌓인다.
지금 기획에는 **거래소 등록**밖에 출구가 없는데, 그러면 낮은 등급이 갈 곳이 없다.

| 가치 | 처분 | 이유 |
| --- | --- | --- |
| **낮음** (Common·Uncommon) | **즉시 판매 → 골드** | 거래소에 올려도 **팔리지 않는다.** 쌓아 두면 인벤만 찬다 |
| **높음** (Rare~Mythic) | **즉시 판매 또는 거래소 등록** | 유저 간 경쟁의 대상 |

> 낮은 등급은 그냥 빨리 팔아 골드를 벌고, **그 골드로 더 비싼 것을 산다.**
> 값싼 산출물이 죽은 재고가 되지 않는다.

### 4.3 구현 접점

| 항목 | 내용 |
| --- | --- |
| `Item.xlsx` | **`BasePrice` 컬럼 추가** — 즉시 판매가의 기준 ([아이템](../../아이템/README.md) 5장에 이미 후보로 있다) |
| 수정 위치 | 엑셀에서만 수정하고 `GameDesign/generate-tables.ps1` 실행 |
| 권위 | 판매·정산은 **전부 서버**. 클라 계산을 신뢰하지 않는다 |

### 4.4 경제에 미치는 영향 — 두 가지

**① 즉시 판매가가 거래소 가격의 바닥이 된다.**
누구도 즉시 판매가보다 싸게 거래소에 올리지 않는다. 결과적으로 **가격 하한이 생기고**,
[거래](../../거래/README.md) 2장의 권장안 **D(자유 거래 + 가격 상하한)** 의 하한 절반을
별도 설계 없이 얻는다. 시세 조작 방어에 유리하다.

**② 즉시 판매는 골드 faucet이다. sink가 반드시 함께 필요하다.**
[`기획평가.md`](../../기획평가.md) 2.2의 🔴 R2가 여기서 다시 나온다 —
골드를 버는 길을 열면서 쓰는 길을 안 열면 **골드만 무한 누적된다.**

| sink 후보 | 강도 | 비고 |
| --- | --- | --- |
| **상점 — 작업슬롯 확장권** | 강함 | 슬롯은 곧 재화 생성량의 배수다. 일감 T-012·경제와 함께 정해야 한다 |
| **상점 — 가챠(캐릭터 모집) 티켓** | 지속 | 캐릭터 획득 경로와 연결 (7장) |
| **거래 수수료** | 상시·완만 | 자전거래를 손해로 만든다 |

> ⚠️ **최소 두 개는 있어야 한다.** 상점 품목과 가격은 아직 전부 가정이며,
> [게임 UI](../../게임UI/README.md) 6장 Q9(상점이 골드 상점인가 현금 상점인가)가
> 여기서 **"골드 상점"** 쪽으로 답이 잡힌다. 수익화(BM)는 여전히 미정이다.

## 5. 성장 — 캐릭터 레벨과 계정 레벨의 분리

### 5.1 두 갈래 경험치

```
자원 ──┬─→ 즉시 판매 ─────────────────→ 골드
       └─→ 캐릭터에게 먹이기 ──────────→ 캐릭터 레벨 ↑

캐릭터가 작업 ─→ 캐릭터 경험치 ↑ ─(일정 비율)─→ 계정(섬주인) 경험치 ↑ ─→ 전역 특성
```

| 성장 축 | 경험치 획득 경로 |
| --- | --- |
| **캐릭터 레벨** | ① 슬롯에 배치돼 작업하면서 획득 ② **자원을 먹여서** 획득 |
| **계정 레벨** | **오직 캐릭터가 작업으로 벌어온 경험치의 일부**만 |

### 5.2 왜 계정 경험치를 작업으로만 제한하는가

**계정 특성은 전역이기 때문이다.** 자원을 사서 먹이는 것만으로 전역 특성을 올릴 수 있으면,
골드로 계정 레벨을 사는 길이 열린다. 계정 레벨을 **"캐릭터를 굴린 시간"** 에만 묶어 둔다.

### 5.3 얻는 것

- **자원 먹이기가 자원 sink를 겸한다** — 3.3에서 산업별 특성을 폐지하며 사라진
  자원 소비처를 그대로 대체한다.
- 배치된 캐릭터가 스스로 성장하므로, **오래 굴린 캐릭터에 애착이 생긴다.**
- **일감 T-003(캐릭터 성장, 현재 보류)이 요구하던 "경험치 획득 경로"의 답이 된다.**
  T-003은 `경험치 획득 경로 · 레벨업 곡선 · 적성 기여식` 셋이 정해지길 기다리는 중이다.

### 5.4 ⚠️ 자기가속 루프를 조심해야 한다

```
계정 레벨 ↑ → 작업슬롯 ↑ → 캐릭터 경험치 총량 ↑ → 계정 레벨 ↑ → …
```

[`게임기획코어.md`](../../게임기획코어.md) 4장이 이미 경고한 구조와 같은 형태다 —
*"총량 = 접속 시간 × 슬롯 수 × 속도 배수 — 세 항이 전부 곱셈이다."*
여기에 **레벨이 슬롯을 늘리는 되먹임**이 붙는다.

- 곡선 없이 풀면 상위권이 기하급수로 벌어지고 신규 유저가 영원히 못 따라잡는다.
- **일감 T-012(최대 슬롯 증가 곡선)의 우선순위가 올라간다.**
  계정 레벨 곡선과 슬롯 해금 곡선을 **함께** 잡아야 한다.

## 6. 섬 가치 랭킹

### 6.1 제안

유저들끼리 **섬의 가치를 합산해 1~1000위를 공개**한다. 경쟁심을 자극하는 명예 요소다.

- 승패 조건이 없는 게임에서 **장기 목표를 대신한다** ([`기획평가.md`](../../기획평가.md) R3).
- [진행 및 성장](../../진행%20및%20성장/README.md) 2.3이 *"랭킹·시즌·수집 도감 중 최소 하나는 필요하다"*
  고 적어 둔 자리를 채운다.
- 1장의 섬 컨셉과 직결된다 — **"내 섬이 남의 섬보다 잘 개발됐는가."**

### 6.2 점수 기준 — ❌ 미확정

**세 후보 중 무엇으로 매길지 아직 정하지 않았다.**

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| **총자산 평가액**<br>(골드 + 보유 아이템 × 거래소 시세) | 거래소와 직결되어 P4(모든 재화는 흐른다)와 정합적 | 시세가 흔들리면 순위도 흔들린다. **자전거래로 조작 여지** |
| **종합 개발도**<br>(계정 레벨 + 슬롯 수 + 캐릭터 + 특성 + 자산의 가중합) | 섬 개발 컨셉과 가장 맞고, 시세 변동·조작에 둔감 | **가중치 설계가 필요하다** |
| **누적 산출량**<br>(지금까지 캔 아이템 총합) | 계산이 단순하고 조작이 어렵다 | 사실상 "접속 시간 × 슬롯 수" 랭킹 — **신규 유저가 영원히 못 따라잡는다** |

### 6.3 ⚠️ 랭킹만으로는 부족하다

**어느 기준을 골라도 1000위 밖 유저에게는 동기가 없다.**
상위권은 고이고 신규 유저는 진입 자체가 불가능해진다.

| 보완 후보 | 내용 |
| --- | --- |
| **시즌 리셋** | 일정 기간마다 랭킹을 초기화한다. 새로 시작할 이유가 생긴다 |
| **구간 리그** | 비슷한 규모끼리 묶어 경쟁시킨다. 1000위 밖에도 경쟁 상대가 생긴다 |

시즌·리그 도입 여부는 [진행 및 성장](../../진행%20및%20성장/README.md) 5장의 미결 항목과 함께 정한다.

## 7. 캐릭터 — 다종족과 획득 경로

### 7.1 종족을 여러 개 둔다

**사람 · 몬스터 등 여러 종족**이 캐릭터로 들어갈 수 있게 한다 (팰월드 느낌).

- 종족은 **외형과 산업 적성 분포의 차이**로만 표현한다.
  예: 몬스터 계열은 사냥 적성이 높고 농사 적성이 낮다.
- **종족을 별도 시스템 축으로 만들지 않는다.** 종족 상성·종족 전용 스킬 같은 것을 얹으면
  적성·장비·특성 위에 네 번째 축이 생겨 밸런스 항이 하나 더 늘어난다.

### 7.2 획득은 가챠 티켓으로 일원화

| 항목 | 내용 |
| --- | --- |
| 경로 | **채취 공통보상의 가챠 티켓** — 유일한 획득 경로 |
| 근거 | 티켓은 이미 **전 산업 공통 별도 롤**로 확정돼 있다 ([아이템](../../아이템/README.md) 1.4) |
| 구현 | 기존 가챠 코드(`Server/WSGameServer/Gacha/`)를 그대로 쓴다 |
| 보조 경로 | 상점에서 골드로 티켓 구매 (4.4의 sink 겸용) |

> 사냥 슬롯에서 몬스터를 포획하는 방식도 검토했으나, **드롭 테이블이 복잡해지고
> 산업 간 비대칭이 생겨** 채택하지 않았다. 종족 차이는 가챠 풀 안에서 표현한다.

### 7.3 데이터 영향

| 대상 | 조치 |
| --- | --- |
| `CharacterTable` | **`Race` 컬럼 추가** — `Enum.xlsx`에 `CharacterRace` enum 신설 |
| `CharacterTID 1` | **폐기 · 결번** (3.2) |
| 수정 위치 | `GameDesign/Excel/`에서만 수정 → `generate-tables.ps1` 실행 → 생성물 같은 커밋에 |

> **enum은 뒤에만 추가한다.** `CharacterRace`는 신규라 문제없지만,
> 값을 중간에 끼우면 DB에 저장된 정수의 뜻이 바뀐다
> ([`게임기획코어.md`](../../게임기획코어.md) 4장).

**이 절의 내용은 일감 T-010(캐릭터 시스템 기획 문서화)의 재료다.**

## 8. 작업슬롯 연출

### 8.1 지금 목업의 표현을 바꾼다

현재 `게임UI목업.html`(v1 · 폐기)의 작업 슬롯은 **텍스트 + 슬라이더**다.
생각하고 있던 그림은 다르다.

| | 현재 목업 | **이 제안** |
| --- | --- | --- |
| 슬롯 표시 | 텍스트 + 진행 슬라이더 | **캐릭터 + 자원에 맞는 배경**(나무·돌·몬스터 등)이 생성되고, 앞으로 나가 캐고/치는 모션 |
| 슬롯 클릭 | 캐릭터 배치 목록(picker) | **해당 슬롯의 상세 세팅 화면** — 캐릭터 배치 · **장비 착용** · 수치 확인 |

### 8.2 연출은 큰 창에서만 돌린다

| 레이어 | 표현 |
| --- | --- |
| **상시 위젯** (바탕화면 상주) | **텍스트 + 게이지 유지.** 연출 없음 |
| **작업장 패널** (필요할 때 여는 큰 창) | **배경 · 캐릭터 · 공격 모션** |

**근거 — 상시 실행 앱에서 리소스는 기능이 아니라 생존 조건이다.**

- [게임 UI](../../게임UI/README.md) 3장: *"게임 때문에 노트북이 느려진다는 즉시 삭제 사유다."*
  [`기획평가.md`](../../기획평가.md) R10도 같은 지적을 한다.
- P1(조용할 것) — 바탕화면에서 상시로 움직이는 캐릭터는 업무 중 시선을 끈다.
- **창을 닫으면 그리기를 멈춘다.** 보고 있지 않을 때 CPU가 0에 수렴한다.

### 8.3 ⚠️ 연출은 값의 진실이 아니다

[작업슬롯](../../작업슬롯/README.md) 3.2·7장의 확정 사항을 지킨다.

- **판정은 서버 권위**다. 클라이언트는 `CurrentWorkSpeed`·진행도·1판정비용을 받아
  **로컬 타이머로 그림만 만든다.**
- 클라이언트의 카운트다운·모션이 서버와 어긋나도 문제되지 않는다.
  **다음 푸시에서 서버 값으로 교정**된다.
- **초당 수십 번 도는 루프를 두지 않는다** — 이건 서버 쪽 규칙이지만,
  클라 연출도 창이 열려 있을 때만 프레임을 쓴다.

**이 절은 일감 T-006(작업슬롯 UI)의 시각 요구사항이다.**
