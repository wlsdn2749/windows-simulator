# T-012 최대 슬롯 증가 곡선 결정

## 배경

**슬롯 수가 곧 경제 총량의 배수다.** 슬롯이 2개면 재화가 2배로 생긴다.
~~시작 슬롯 수·증가 수단·상한이 전부 미정이라~~ **셋 다 2026-08-01에 확정됐는데**,
서버는 아직 확정 이전의 임시값으로 돌고 있다.

```csharp
// Server/WSGameServer/User/User.WorkStation.cs — 2026-08-02 확인
/// <summary>신규 유저에게 기본으로 열어 주는 작업슬롯 수. 시작 슬롯 수가 미확정이라 1개로 둔다.</summary>
public const int DefaultSlotCount = 1;   // ⚠️ 확정값은 2. 주석도 낡았다
```

> ⚠️ **상한 8을 강제하는 코드도 없다.** 슬롯 해금 경로가 아직 없어서 당장 문제가 되진 않지만,
> 해금을 붙일 때 함께 넣어야 한다.

> ✅ **시작 2 · 상한 8은 곡선과 무관하게 지금 반영할 수 있다.** 아래 곡선(미정)을
> 기다릴 필요가 없는 항목이다 — 상수 두 개와 주석만 고치면 된다.

## 2026-08-01 확정 — 구조는 정해졌다

| 항목 | 값 |
| --- | --- |
| 시작 슬롯 수 | **2개** |
| 상한 | **8개** |
| 증가 수단 | **계정 레벨(상한) × 골드(구매)의 이중 게이트** |

| 한쪽만 쓰면 | 문제 |
| --- | --- |
| 레벨만 | 슬롯 확장이 sink가 아니게 된다 |
| 골드만 | `골드 → 슬롯 → 골드` 자기가속이 폭주한다 |

**남은 것은 곡선이다** — 레벨 N에 상한 몇 개인가, 슬롯 N번째의 가격은 얼마인가.

## 할 일

- [x] 시작 슬롯 수 결정 → **2**
- [x] 증가 수단 결정 → **레벨 × 골드**
- [x] 상한 결정 → **8**
- [ ] **레벨별 상한 곡선** (레벨 N에 몇 개까지)
- [ ] **슬롯별 구매 비용 곡선**
- [ ] 거래소 경제와의 관계 검토 — 슬롯이 곧 faucet 배수다
- [ ] `DefaultSlotCount` **1 → 2로 교체** + 낡은 주석 정정 (**곡선을 안 기다려도 된다**)
- [ ] 상한 8 검증 추가 (해금 로직과 함께)
- [ ] 해금·구매 로직 구현

## 완료 조건

"레벨 N이면 슬롯 M개까지, 각 슬롯의 가격은 얼마"가 데이터로 정해지고,
서버가 그에 따라 슬롯을 연다.
