# T-001 하트비트로 끊김 감지

## 배경

오프라인 진행을 폐지하면서 **접속 판정이 곧 재화 생성 조건**이 됐다.
지금은 TCP가 끊겨야 세션이 정리되는데, 그 사이(랜선을 뽑거나 PC가 절전에 들어간 구간)는
서버가 여전히 "접속 중"으로 보고 채취를 계속 굴린다. **그만큼이 공짜로 얻는 진행**이다.

TCP는 끊김을 즉시 알려주지 않는다. RST가 오지 않는 종류의 단절(전원 차단·네트워크 소실)에서는
OS 기본 keepalive가 돌 때까지 수 시간이 걸릴 수도 있다.

## 완료 조건

랜선을 뽑은 뒤 **정해진 무응답 시간 안에** 세션이 정리되고, 그 이후 구간의 채취가
정산되지 않는다. 순단(짧은 끊김) 후 재접속했을 때의 동작이 결정한 대로 나온다.

→ **코드는 완료. 실기 재현(Unity 플레이 중지·랜선 뽑기) 확인이 남았다.**

## 구현 요약

**살아 있음의 증거는 수신뿐이다.** `Send`는 소켓 쓰기가 아니라 큐 적재(용량 1024)라
소켓이 죽어도 성공한다 — 송신 성공은 연결의 증거가 되지 못한다.

| 위치 | 내용 |
| --- | --- |
| `MikaNetwork.Server/IHeartbeatSession.cs` | 유휴 판정용 좁은 면. **`ISession`에 얹지 않았다** — Unity에 수동 사본이 있고 유휴 판정은 서버만의 관심사다 |
| `MikaServerSession` | `LastReceivedAt` 추가(수신 시 갱신) · `Disconnect()`를 `Interlocked`로 멱등화 |
| `MikaServer.DisconnectIdle` | 세션 목록·시각·임계값을 인자로 받는 본체. **주기·임계값을 Lib이 정하지 않는다** |
| `WSGameServer/Common/SessionWatchdog.cs` | 5초 타이머 → 로직 스레드에서 스윕 |
| `Global.SessionIdleTimeout` | **15초** |
| `Entity.Destroy()` | 멱등 가드 — 여러 경로에서 들어와 종료 정산이 중복되던 것 |
| `UserManager.CreateUser` | pid 중복 시 **기존 세션을 끊고 새 로그인을 받는다**(기존: 무응답 return) |
| `UserManager.LeaveUser` | **값 일치 제거**로 바꿔, 좀비의 늦은 정리가 살아 있는 세션의 매핑을 지우지 않게 했다 |
| `EResultCode.AlreadyLoggedIn = 2` | 같은 세션의 중복 로그인 요청에 응답 |

테스트 11건 추가(108 → 119). 유휴 스윕 6건 + 정리 멱등·매핑 정합성 5건.
