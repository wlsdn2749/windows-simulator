# T-018 `BasePrice` 컬럼 추가 · 150종 가격 결정

## 배경

2026-08-01에 **즉시 판매**가 확정되면서 `Item.xlsx`의 `BasePrice`가
**후보에서 필수로** 올라갔다 → [거래](../GameDesign/기획/거래/README.md) 3.1.

**이 컬럼이 없으면 경제가 한 줄도 구현되지 않는다.**

| 막히는 것 | 이유 |
| --- | --- |
| 즉시 판매 | 판매가의 기준이 없다 |
| 거래소 가격 하한 | **하한 = 즉시 판매가**로 설계돼 있다 (D안 밴드의 절반) |
| 상점 가격 · 슬롯 확장권 | 골드의 가치 척도가 없다 |
| 섬 가치 랭킹의 자산 항 | 아이템을 골드로 환산할 수 없다 |

## 할 일

- [ ] `Item.xlsx`에 `BasePrice` 컬럼 추가 (`Type = int`, `Min = 0`)
- [ ] **150종 전부에 값 입력** — 5산업 × **5레벨** × 6등급
- [ ] 즉시 판매가 = `BasePrice`의 몇 %인지 결정 (거래소 하한과의 관계)
- [ ] `GameDesign/generate-tables.ps1` 실행 · 엑셀 + 생성물 같은 커밋

## 지켜야 할 것

- **희귀도가 오를수록 가격도 오르는 단조 증가**를 유지한다.
  어긋나면 상위 등급을 갈아 하위를 사는 재정거래가 생긴다.
- ⚠️ **단조 증가가 2차원이다 (2026-08-02).** 산업 레벨이 생기면서 축이 `희귀도 × 레벨`이 됐다.
  **레벨이 오를수록도 비싸야 한다** — 상위 레벨은 판정이 1/3씩 느려지므로
  가격이 벌충하지 않으면 아무도 상위 레벨을 돌리지 않는다.
  → [산업 레벨](../GameDesign/기획/자원채취/산업레벨.md) 2.4 · 7장 8번
- 산업 간 가격은 **회당 산출(T-009)·희귀도 분포(T-008)와 함께** 봐야 시간당 수익이 맞는다.
  세 일감을 따로 정하면 특정 산업만 압도적으로 돈이 된다.

## 완료 조건

150종 전부에 `BasePrice`가 들어가고, 서버가 즉시 판매가를 계산할 수 있다.
